## Collection map (`src/collections`, globals in `src/globals`, blocks in `src/blocks`)

- Identity: `users` (roles admin|editor, only panel users) · `customers` (portal auth, verify email, company/tax/phone).
- Catalog: `product-families` → `products` (drafts, blocks `layout`, features/specs/requirements) → `editions` (sku (stable quote identifier), licenseType, durationMonths, seats).
- Marketing: `solutions`*, `industries`, `case-studies`*, `posts`*, `careers`, `partners`, `pages`*, `media`.
- Support: `docs`* (slug unique per product+locale), `releases` (unique product+version), `downloads` (file→media, os, access public|licensed), `faqs`, `support-tickets` (messages array).
- Licenses: `licenses` (CSPRNG key unique, product denormalised from edition).
- Sales (P2-S, payments still off): `orders` (orderNumber/idempotencyKey unique, items[].license, billing TCKN/VKN, consents) and `payment-events` (eventKey unique, body SHA-256 only). Store `src/lib/payments/store/**` (BEGIN IMMEDIATE, conditional writes, one licence per order). Editions `saleMode`/`pricing.*Minor` and `site-settings.commerce.{mode,providers,vat,quoteSince}`: staff read, admin write (commerce switch panel-only, not API key), never in content:import.
- Plugin: `forms`, `form-submissions`, `search` (products, docs, faqs, posts). Globals: `header`, `footer`, `site-settings`.
- `*` = drafts+versions. Content fields `localized`; slugs via `slugField()` (`src/fields/slug.ts`): auto from title, unique per locale.

## Access rules (`src/access`)

- Payload default access is `Boolean(user)` and customers ARE users: every collection/global/plugin collection must set explicit access.
- Admin panel: `users` with role admin/editor only; `customers.access.admin = false`.
- Content: public read (`publishedOrStaff` for drafted collections; `careers` only `isOpen`); write = admin/editor.
- `licenses`: read = admin or owner customer; create/update/delete = admin only. Server code uses `overrideAccess: true`. Customers NEVER write them.
- `support-tickets`: read/update = staff or owner; customers create for themselves and may only append messages (hook-enforced).
- `downloads`/`media`: `public` for everyone; `licensed` only for staff or customers with a valid license (active, started, not expired) for the product. `downloads` hook syncs `media.visibility/licensedProducts` (fail-closed).
- Staff panel sessions and customer owners can read `orders` in any commerce mode. Provider references and failure codes are staff-only, and billing and consents are visible to panel admins and owners. Order creation is server-only via `overrideAccess`. Deletion is disabled. Panel admins can edit invoice, notes and requiresReview. `payment-events` grants read access to panel admins and reserves writes for the server. `integrations` grants read and update access to panel admins. All three exclude users API keys through REST, GraphQL and MCP.
- Admins manage `users`, staff can edit themselves, and the roles field is admin-only. The first user becomes an admin. Users API keys cannot mutate `users` or `customers` accounts. Admins can update `site-settings`, with commerce settings restricted to admin panel sessions.

## Promotion, quotes and license assignment

- No online payment. Every edition has `Teklif İste` (Request a Quote); SKU is the language-independent edition identifier.
- An administrator assigns licenses through the admin panel or an authorized API/MCP; the existing admin-only write access is preserved. Customers can never create or update licenses.
- The key is generated on the server during create with `src/lib/licenses/generate.ts`. Product and seat count come from the edition; subscription end is start + months of duration.
- If the SMTP host is empty or starts with `CHANGE_`, the Payload console adapter is used.

## Payments: checkout and orders (P5)

- The purchase surface is open only while `getCommerceState().checkoutOpen` is true: env `PAYMENTS_ENABLED=true` + site mode `payments` + provider + VAT + legal pages ready. With the default setup, everything is in quote mode. The `CHECKOUT_READY` flag set to true does not open anything on its own.
- Routes: TR `/hesap/satin-al/[sku]`, `/hesap/siparisler[/no]` ↔ EN `/account/checkout/[sku]`, `/account/orders[/no]`. When checkout is closed or the edition cannot be purchased, the user is redirected to the quote page (fail-to-quote); orders are always visible read-only in every mode. A customer gets a 404 for another customer's order number.
- `startCheckoutAction` (`src/lib/portal/checkout-actions.ts`) → `createCheckoutOrder` (`src/lib/payments/checkout.ts`): price/VAT/provider/contract text are computed on the server; the amount is never read from the form; the same form token produces only one order; contract copy is in `src/lib/payments/contract.ts`. Works without JS (POST→303).
- Callback 303 target is the relative `/{locale}/hesap/siparisler?donus=1`; the page redirects to the logged-in customer's latest order (the number is never carried in the URL).
- **The build environment must have `PAYMENTS_ENABLED=true`:** when the capability is on, `[locale]/layout.tsx` calls `commerceRenderBoundary()` (`src/lib/commerce/state.ts`) and all site pages are rendered per request; build constant `__SOFTMARKET_BUILD_PAYMENTS__` (`next.config.ts`). In a capability build, `contentStaticParams` returns a single catch-all path per route (`__dynamic__`), so a route with an empty list does not remain an ISR fallback. A build without the capability combined with a process that has it = payments hidden (falls back to closed, `noStore` is not called), and a rebuild is required. Calling `getCommerceState()` only in some data paths is not enough by itself (P6 finding: "Page changed from static to dynamic at runtime" → 500); a new reader must sit under the `[locale]` layout (tested).
- Isolated e2e: `E2E_NEXT_DIST_DIR=.next-<name> pnpm test:e2e:isolated` (build environment `PAYMENTS_ENABLED=true` + copied DB); the fake iyzico `scripts/e2e-fake-iyzico.ts` (port 3500) requires a separate `SOFTMARKET_E2E_BUILD=1` build and `assertIsolatedE2E`; do not deploy this build.

## Payments: admin operations (P6)

- Order document side panel "`Sipariş işlemleri`" (Order actions) (`ui` field, `src/admin/fields/order-actions*.tsx`): **`İade et`** (Refund) (paid/fulfilled, full amount), **`İptal et`** (Cancel) (pending), **`Bildirimi yeniden gönder`** (Resend notifications). Endpoints `POST /api/orders/:id/{refund,cancel,resend-notifications}` (`src/lib/payments/admin-endpoints.ts`): only an admin **panel session** (cookie, `_strategy=local-jwt`, no `Authorization` header) + same origin; anonymous 401, editor/customer/API key/MCP 403.
- Refund protocol (`src/lib/payments/admin-actions.ts`): first `provider.refundStatus()` (iyzico `/v2/reporting/payment/details`, Stripe PaymentIntent) → one lock per order (`payment-events` `<provider>:admin-refund:<no>`) → a single `refund()` → in one transaction `refunded` + licenses `revoked`. On timeout/uncertain response: **no blind retry**; the order becomes `requiresReview` (`refund_uncertain`), and reconcile only reads. Refund e-mail goes through the durable queue (`notify.ts` type `refund`, marker `<provider>:refund-notice:<no>`); schema unchanged.
- Stripe `charge.dispute.created` → licenses `suspended` + review; `charge.refunded` → provider read and `refunded`. There is no dispute notification for iyzico (manual). Operations: `docs/payments/operations.md`.

## Phase 8a: JSON content import

- `pnpm content:import [directory|file.json] [--dry-run] [--legal]`; default `content/seed`. `make seed` = ensure-forms + content:import.
- Format: `content/seed/schema.json`; each record in every collection array is `{ "tr": { ...Payload fields }, "en": { ...Payload fields } }`. Common fields and array/block order are the same in both languages; localized fields may differ. `version: 1` is required. Price/ID are not accepted.
- Relationships target the **TR slug** value; editions = SKU; docs = `product-tr-slug/doc-tr-slug`; releases = product+version identity. Form references are the fixed `title` values from ensure-forms. Multi-collection link: `{ "relationTo": "products", "value": "ornek-urun" }`.
- Rich text: `{ "markdown": "# Heading\nText" }`.
- Internal site links (header/footer/blocks): `{ "type": "route", "route": "urunler", "label": "…" }`; dynamic path `{ "route": "yasal_slug", "routeParam": "eula" }`. Keys are in `src/i18n/paths.ts` `LINK_ROUTES`; do not write URLs with a `/tr`/`/en` prefix. Accent color `site-settings.brand.accent` (hex, WCAG AA rule `src/lib/brand.ts`), `motion: subtle|none`. Globals: `globals: { "header": { "tr": {...}, "en": {...} }, ... }`.
- Media: `media: [{ "path": "media/screen.png", "alt": { "tr": "Ekran", "en": "Screen" }, "protected": false }]`; the file is in `content/seed/media`, and the field reference is `"heroImage": "media/screen.png"`. File names must be unique within the seed. Media is upserted by the `seedPath` field; identity is kept even when Payload resolves file name conflicts. Public images explicitly set `protected:false`.
- Slug/SKU identity is fixed: changing one is accepted as a new record. Running the same files again does not create record/array/block copies. The schema file is not imported.
- If a product in the editor has moved to composition mode, its latest draft/autosave layout is preserved during import (including when the seed uses the old layout and with `--dry-run`): the layout is extracted from the TR/EN writing and from the relationship/Markdown conversion; other fields are updated, the warning `` `warn products:<tr-slug> layout korundu (editörde düzenlenmiş)` `` is printed, and there is no error or exit≠0. The import still publishes; a composition that exists only in the draft also goes live. The layout structure is shared, block-internal texts are localized; a seed carrying a bound block in only one language is rejected before writing. If the seed is also in composition, it is written with the V2 validations. Other collections are not affected.
- `--legal`: `content/legal/{tr,en}/*.md` → pages (`pageType: legal`, file name is the slug), Payload Markdown→Lexical; **publishes**. Use when the legal drafts are ready; the default command does not import legal files.
- The CLI uses a single DB transaction; errors are reported with file + collection + identity. SQLite rollback does not restore media files.

## Page builder (F6): home page, system pages, landing pages

- The home page is a `pages` record. Resolution order: `site-settings.homePage` → slug `home` → built-in fallback (`src/components/home/fallback-home.tsx`). Only **published** records are visible; drafts never reach visitors. `/home` → `/` (308).
- Blocks in the `layout` array render in order; the first `hero` is the page's h1. The home page seed is `content/seed/05-pages.json` (an exact equivalent of the current layout: hero `aside: families`, productFamilies, solutionsGrid, logoWall, caseStudy, newsList, cta). Appearance: `appearance.{theme,spacing,align,width,animation,anchor,hidden,separator}`.
- Motion (V1, `src/fields/block-motion.ts`; excludes spacer/divider/listing): `motion.preset` auto|none|fade|slide-up|slide-down|slide-left|slide-right|zoom-in|parallax-soft|stagger, `trigger` scroll|scroll-progress|load|hover, `duration` fast|base|slow, `delay` "0"|"100"|"200"|"300", `easing` soft|standard|emphasized, `stagger` none|tight|relaxed, `mobile` (parallax). Defaults keep the old look; `appearance.animation: none` turns all of it off. Hero accepts only auto/none/slide-*/parallax-soft; an effect that would hide the first block + hero is downgraded to slide on the server (LCP). CSS contract: "Motion system" in `globals.css` + `src/lib/anim.ts`.
- System pages: `pages.systemKey` ∈ `products|solutions|news|customers|careers|partners|support|contact|about` (one record each) → `hero` (eyebrow/title/lead/actions; an empty field = i18n) + the blocks for that route. The listing's position is the `listing` block; if there is no block, the list appears below the hero and is hidden with `appearance.hidden`. Without a record, the route keeps its old layout.
- Landing: `pageType` standard/landing + `systemKey` empty → `/tr/<slug>`, `/en/<en-slug>`. Slugs that match a route folder or an EN translation (`urunler`, `products`, `hesap`, `admin` …; `RESERVED_SLUGS` in `src/lib/system-pages.ts`) are rejected. Link: `type: internal` + pages reference (slug per language), or `type: route`, `route: slug`, `routeParam: <tr-slug>`.
- `pageType: template` is never public (no anonymous read, route, or sitemap); start a new page with Payload "Duplicate" (systemKey is cleared in the copy).
- Publishing (`_status: published`) and global updates refresh the entire site cache (`revalidatePath('/', 'layout')`); draft/autosave does not refresh it. The CLI (`content:import`) cannot reach the Next cache: on a live process it refreshes within at most 1 hour, or with a publish from admin/API.
- Home page block order via MCP (admin API key; `pages` CRUD is open):
  1. `findPages` with `where: JSON.stringify({ slug: { equals: "home" } })`, `locale: "tr"`, `depth: 0` → `id` and `layout`.
  2. Send the **entire** `layout` array in the new order (keep block `id`s; omitted blocks are deleted): `updatePages` `{ id, locale: "tr", layout: [...], _status: "published" }`. Block structure is language-independent; to change only text, send the same order and `id`s for EN with `locale: "en"`.
  3. To move the home page to another record: `updateSiteSettings` `{ homePage: <pageId> }`.
- For bulk/idempotent content, use `pnpm content:import` (slug/TR identity); MCP create is not an upsert.

## Visual editor (V5, Payload-native canvas)

- `pages` + `products` open in Live Preview (`src/editor/canvas/plugin.ts`: `admin.livePreview.openByDefault` + `beforeDocumentControls` host); the form is a narrow side panel (`src/app/(payload)/custom.scss`). Text markers `editText/fieldAttrs/docFieldAttrs` (`block-shell.tsx`); allowed fields are only in `src/editor/canvas/fields.ts` (`INLINE_BLOCK_FIELDS`, `INLINE_DOC_FIELDS`). When adding a new block/text field, add it to the list; `tests/unit/visual-editor-fields.test.tsx` enforces the match between schema and render. Public/ISR HTML does NOT contain `data-block-*`, `data-field-path`, or `data-doc-field`.
- The bridge (`bridge.tsx`) loads only inside `LivePreviewRefresh`, and only inside the iframe, via `React.lazy` (bundle guard). Messages in `protocol.ts` (zod/mini, `ns: sm-canvas`, `v: 2`): origin checked in both directions + `event.source` (iframe.contentWindow ↔ parent) + strict schema; text path allowlist + prototype segment ban; values are flat single-line ≤1000.
- V2 rules are mirrored in the editor (`rules.ts`): productHero is first/locked; productEditions can be moved but not deleted or hidden; bound blocks are not duplicated. On the first structural operation, a compatibility product is materialized into 8 bound blocks (the old filtered duplicates are added hidden).
- Loss/conflict: `admin/sync.ts` sends the same request as the Payload autosave with keepalive PATCH when the tab is hidden or closed (over 60 KB, a `beforeunload` confirmation; UTF-8 bytes).
- **Conditional write (P1):** a virtual hidden `editorVersion` field is added to pages/products (on read = SHA-256 digest of the raw all-locale document snapshot; includes `updatedAt`; no DB column) + the first `beforeChange` hook (`src/editor/canvas/concurrency.ts`). The admin form (visual + classic, autosave/save/publish, flush) carries the version; in the same transaction, if it does not match the digest of the latest draft snapshot, **409**. Writes that do not carry a version (MCP, content:import, Local API, bulk edit) and explicit version restores are unconditional writes; do NOT send `editorVersion` from MCP. On a 409, the editor shows "`Birleştir ve kaydet`" (Merge and save) / "`Değişikliklerimi kopyala`" (Copy my changes) / "`Yeniden yükle`" (Reload). Merging keeps block/array IDs; if the same value/deletion/order conflicts, nothing is written. `editorVersion` cannot be read outside staff; an empty/null value is 400; an old timestamp is 409; it must be the first field (hash taken before locale flatten/populate). Payload `lockDocuments` only blocks other users (not the same user/MCP key/another tab).
- SQLite transactions are serialized within the process (`src/lib/db-serial-transactions.ts`, `payload.config` adapter): libsql opens each transaction on a new connection without a busy timeout, so a concurrent second transaction got SQLITE_BUSY at BEGIN, and later writes could stay invisible. A Local API call inside a transaction must pass `req` (otherwise "write queue timeout" after 5 s).
- Payload internal dependencies (on upgrade, `tests/e2e/isolated/visual-editor.spec.ts` is mandatory): BEM classes `.collection-edit--is-live-previewing`, `.collection-edit__main`, `.live-preview-window`, row `#layout-row-N`, `.collapsible-field__collapsible.collapsible--collapsed .collapsible__toggle`, form actions `SET_ROW_COLLAPSED` / `REPLACE_STATE` / `DUPLICATE_ROW`, `#action-save`, `config.blocksMap`.

## Payments P4: webhook, callback, reconcile

- Routes (POST only): `/api/payments/iyzico/webhook`, `/api/payments/iyzico/callback`, `/api/payments/stripe/webhook`. If `PAYMENTS_ENABLED` is not `true`, respond 404 without touching the DB; when the Stripe adapter is off, 404. Logic is in `src/lib/payments/{events,sync,fulfill,reconcile,runtime,body}.ts`; the route files only wire it up.
- Event = trigger, provider = truth: signature → `payment-events` record → server `retrieve` → conditional status transition → `fulfilPaidOrder` (one transaction, one license) → durable notification queue after commit (`src/lib/payments/notify.ts`). Amount/currency/reference mismatch = `requiresReview`, no license; alert `PAYMENTS_ALERT_EMAIL`.
- Webhook bodies are bounded at 256 KB. After the 72-hour quote-mode drain, signed payment events and unmatched lifecycle events are journaled as `ignored` with 200. Signed Stripe refunds and disputes linked to existing orders still apply while the payments capability and the Stripe adapter are enabled. Unverified requests outside the drain return 404 and processing failures return 500.
- Browser returns use separate iyzico and Stripe process-local budgets of two provider syncs per token and 60 requests per trusted IP (IPv6 /48) per minute. Returned orders outside the browser's eligible states skip provider sync. Webhooks and reconciliation handle late payments.
- Notification persistence: `orders.notifications` (staff-only, server-written) `confirmationSentAt/licenseSentAt/reviewAlertSentAt` + `attempts/lastError/nextAttemptAt/leaseUntil`. Sending happens after commit; a conditional lease per order (a second concurrent sender stops); on each success, the marker is set `WHERE <field> IS NULL`. Reconcile retries unmarked `fulfilled`/`requiresReview` orders (≤7 days) up to 5 attempts with 15/30/60/120 min backoff; if SMTP (for the alert, `PAYMENTS_ALERT_EMAIL`) is absent, it skips without counting. Order licenses are created with `ORDER_FULFILMENT_CONTEXT` → the license hook sends no e-mail (single send from the queue); the hook for manually assigned licenses still works as before via `after()`. Delivery is at least once: if the process dies between sending and writing the marker, one repeat is possible.
- `pnpm payments:reconcile [--dry-run]` + `deploy/payments-reconcile.{service,timer}` (15 min). Do not write e-mail/TCKN/VKN/keys/body to logs (tested). Do not import payments server modules from `'use client'` files (`payments-p4.test.ts` scans the graph); the `server-only` package is not used because it breaks the CLI/tests.

## Licensing core (L1 schema, L2 signing, L3 client API, L4 updates and downloads, L5 rules, L6a/L6b security center, L7a portal devices, L8 identity and webhook anomalies, L9 client integration kit)

- Plan and implementation records in `docs/plan-licensing-security.md`, ADR in `docs/licensing/adr-l0.md`. Enum values live in `src/lib/licensing/constants.ts`.
- New collections (group Security): `license-activations`, `license-status-log`, `security-events`, `security-blocks`, `security-audit`. Read = admin **panel session** only (`isPanelAdmin`: `local-jwt` with no Authorization header). Create/update/delete require server code with `overrideAccess: true`. No versions or document locks. `graphQL: false`; NOT in the MCP allow-list; no public revalidation. Never log or store full IPs, raw fingerprints, license keys or e-mails in these rows.
- Global `licensing-settings` is readable by panel admins. The same-origin admin panel session can save non-secret fields, including `apiEnabled`, rule thresholds and `rules.observeUntil`. Server code owns `signingKeys`. The API defaults to off and rules default to `notify`. A rule can suspend only in `suspend` mode after a valid `rules.observeUntil` has elapsed. The global has no versions, document locks, GraphQL, MCP or content import access.
- L2 server crypto in `src/lib/licensing/crypto/` implements the Ed25519 lease JWS, raw-body request/response canonical strings, and purpose-specific HKDF/HMAC. IP persistence uses only IPv4 /24 or IPv6 /48 and a UTC-month-scoped hash. Mapped IPv6 uses its IPv4 identity.
- `pnpm licensing:keygen` provisions on the configured deployment DB. Keygen stores PKCS#8 in the `integrations` vault under `licensing-signing-ed25519` and returns public metadata. An active key requires explicit `--rotate`. `SOFTMARKET_LICENSE_SIGNING_KEY` takes precedence over the vault. Use `--register-env` to register only its public metadata and include `--rotate` to replace an active key. An invalid or mismatched env key disables signing. Retired keys verify for 90 days and `revokedAt` ends verification immediately.
- `GET /api/v1/licensing/keys` publishes public signing metadata. It returns `{ keys: [{ kid, alg: "EdDSA", x }], revokedKids }` with a one-hour public cache or `503 unavailable` with `no-store` when disabled or uninitialized. Programs pin trusted public keys.
- `licenses`: `publicId` (server CSPRNG, immutable), `maxDevices` (positive safe integer), `statusReason/statusSource/statusChangedAt` (server-stamped, admin read). `status` cannot be set or changed with a users API key (MCP/REST; field access strips it). Every status change through Payload writes one `license-status-log` row in the same transaction, including bulk and projected writes (`src/lib/licensing/transitions.ts`); server code declares `req.context.licenseTransition = { source, reason, ... }`. A license with status history or activations cannot be deleted (409). Refund and dispute stamp the same fields and append a payment transition in the order transaction. Refund also revokes active devices. The activation join is readable only by panel admins.
- `products.licensing.{enabled,code}`: staff read, panel admin write, not in content:import; `code` unique, `^[a-z0-9][a-z0-9-]{2,40}$`, immutable once stored (embedded in shipped programs).
- Migration `20261117_200700_licensing_core` is additive (backfill only `licenses.public_id`) with guarded down. Partial unique indexes `license_activations_one_active_fp` / `_one_active_thumb` live only in hand-written migration SQL: any future migration that rebuilds `license_activations` (`__new_license_activations`) must re-create them; `tests/unit/licensing-migration.test.ts` and `licensing-access.test.ts` assert them.
- L3 serves signed raw-JSON `POST /api/v1/licensing/{activate,validate,deactivate}`. Set the global `apiEnabled` and `publicHost`, provision signing metadata and the vault master, and enable the product's licensing code. Clients pin the issuer and public keys. Failures use fixed English codes, and disabled or unavailable service returns 503. See `docs/licensing/client-api.md`.
- Each active device uses a seat. Activation, rebind and deactivation use the shared SQLite `BEGIN IMMEDIATE` writer queue. Mutations and authenticated nonce receipts commit together. Validation jobs already waiting at lock acquisition share a bounded commit with per-request savepoints. Counters and receipts are durable before a lease is returned. An exact, fresh, authenticated deactivate retry is idempotent. Other authenticated replays return 401.
- Token buckets and block cache belong to the single API process. Settings supply the thresholds. Address attribution uses the authenticated Caddy headers, with one shared bucket for unknown addresses. Observational events and last-seen metadata are bounded and coalesced. Rules can report anomalies in L3. The L1 transition guard still owns automatic license suspension.
- L4 adds signed `POST /api/v1/licensing/{updates,downloads/link}` to the durable nonce batch and shared activation limit. Unsigned `GET /api/v1/licensing/dl/<token>` supports a single byte range. HEAD only returns full representation headers. The HMAC bearer link has a 300-second lifetime and five GET admissions in one process. Each transfer rechecks current activation, license, product, and file identity. Restarting the process invalidates existing links.
- Installer bytes come from original uploads referenced by eligible downloads. `UPLOADS_DIR` must be a physical path on Linux or macOS. Descriptor-based confinement rejects symlinks, hard links, and non-regular files. Use private, no-store responses and keep bearer paths out of access logs. Download observations reuse the L3 event writer with prefix-only address attribution and the monthly IP HMAC.
- L5 rules engine (`src/lib/licensing/rules/`): pure rule functions (`rules.ts`: ipSpread `>` threshold, others `>=`; window `now - windowHours < at`; invalid config never hits), pure decision (`decide.ts`), `pnpm licensing:sweep [--dry-run] [--retention]` (`scripts/licensing-sweep.ts`, `deploy/licensing-sweep.{service,timer}` every 5 min). Rules only ever suspend, never revoke; a suspension needs mode `suspend` + valid elapsed `rules.observeUntil` (the L1 hook re-checks and wins), an active license, no suppression, and a closed circuit breaker (`maxAutoSuspendsPerHour`; the N+1th trips it: critical `system.rule_circuit_open`, open until triaged or 24 h). Each hit is one BEGIN IMMEDIATE transaction that re-reads its preconditions; rule events are episodes (one open event per rule+license). Restore core: `restoreRuleSuspension` (`restore.ts`, 409 unless the last status row is that rule suspension; suppression = restore log row / false-positive event within `suppressDays`); its HTTP endpoint is L6b. E-mail queue on `security-events.notify_*` + `detail.notify*` markers (`notify.ts`, lease via `notify_next_at`, 5 attempts, 15/30/60/120 min, no SMTP = not claimed); admin alerts PII-free (`src/lib/email/licensing.ts`), customer suspended/restored e-mails TR+EN. Retention (`retention.ts`) runs in the 04:00 Europe/Istanbul hour or with `--retention`. Record: "L5 implementation record" in `docs/plan-licensing-security.md`.
- L7a portal devices: `/hesap/lisanslar/[id]` (EN `/account/licenses/[id]`, `id` = license `publicId`; foreign/unknown = 404) lists active devices (label, platform, dates, country; never fingerprints/keys/IP). Release = plain `<form action>` `releaseDeviceAction` (`src/lib/portal/device-actions.ts`, no-JS POST -> 303) -> `releasePortalDevice` (`src/lib/licensing/portal-devices.ts`): one serial `BEGIN IMMEDIATE` transaction, ownership re-read under the lock, quota `selfService.portalDeactivationsPer30Days` per license/30 days (0 = off), UPDATE `end_reason customer_portal`, one `activation.ended` event (source `portal`) + one `security-audit` row (actor kind `system`, nonce `portal:<customer>:<token>`), no status-log row (status unchanged). Customer "device released" e-mail via the L5 queue (`customerDeviceReleased`). Record: "L7a implementation record" in `docs/plan-licensing-security.md`.
- L6a read-only security center: custom admin view `/admin/guvenlik` (`src/admin/security/`, registered in `payload.config.ts` under `admin.components.views.securityCenter` + `afterNavLinks`). The view decides access on the server first (`decideSecurityCenterAccess`: admin cookie session only; editor/customer/API-key admin -> `/admin`, anonymous -> login); the nav link is cosmetic. A custom view under a new key gets no template from Payload, so it wraps itself in `DefaultTemplate`. Data comes from `loaders.ts` via the Local API with the requesting admin user and `overrideAccess: false` (never an override read), always with `select`, shaped into view models; loaders also refuse any non-admin-session user. The URL is the only state (GET form, links, `query.ts` allow-lists), no client JS. Privacy: IP prefix plus a 10-char shortened hash only, `detail` flattened and redacted (`format.ts` `safeDetail`), never the license key, customer e-mail, device keys or fingerprint hashes. Labels: `src/lib/security-center-labels.ts` (re-exported from `admin-i18n.ts`). Styles: `.sc-*` in `src/app/(payload)/custom.scss` with Payload theme tokens only. The view itself stays a reader; L6b action widgets are client components that only POST to the endpoints below.
- L6b admin actions (`src/lib/licensing/admin/{actions,endpoints,routes,rules,settings-audit}.ts`), Payload collection/global endpoints, POST only: `/api/licenses/:id/{suspend,revoke,restore,reactivate}`, `/api/license-activations/:id/deactivate` (`mode: release|revoke`), `/api/security-events/:id/{acknowledge,resolve,false-positive,block}` (`restore: true` on false-positive undoes the rule suspension THIS event caused), `/api/security-blocks/add` (not the collection root) + `/:id/lift`, `/api/globals/licensing-settings/rotate-signing-key`. Guard = `guardAdminSession` (P6 matrix: anonymous 401; customer/editor/API key/MCP/bearer/cross-site 403) + `Content-Type: application/json` (415) + body <= 2 KiB. Body: `requestId` (16-64 `[A-Za-z0-9_-]`, idempotency), `reason` (3-500, mandatory), `note?`, license actions `expected: { status, changedAt }` (409 `stale`), events `expectedTriage`; revoke `confirm` = last 6 chars of the license publicId; rotation `confirm` = `DÖNDÜR`/`ROTATE`. Each action = one `withPaymentTransaction` (serial BEGIN IMMEDIATE): receipt lookup (`security-audit.nonce` = `admin:<action>:<target>:<requestId>`; retry -> 200 `replayed`, nothing written), preconditions re-read, status via Local API + L1 context (source `admin`, reason `manual`/`restore`) = exactly one status-log row, exactly one audit row, receipt confirmed after commit. Refusals (409/400) roll back the action and, for an identified caller, write one coalesced `denied` audit row (below). `restore` = rule suspension (L5 `restoreRuleSuspensionTx`) or admin manual suspension; anything else (payment dispute) uses `reactivate`; revoked is terminal. Revoke also revokes active devices; nothing automatic ever revokes. Manual suspend/restore e-mails go through the L5 queue (`license.status_changed` event row, `action_taken=suspended`, `detail.restoredAt`). Block add/lift invalidates the in-process blocks cache (`invalidateLicensingBlocks`); an IP/CIDR block covering the admin's own trusted address needs `confirmSelf: true`. Rotation reuses `provisionSigningKeyTx` (returns kid only), records a high `system.signing_key_rotated` event (admin alert). Panel saves of `licensing-settings` write one `settings.update` audit row (value summary, no e-mails). UI: license sidebar `ui` field `licenseActions` (`src/admin/fields/license-actions.tsx`), signing tab `signingKeyActions`, event/block action columns + "Add block" in `/admin/guvenlik`; all render only for an admin panel session. `licenses.status` is read-only for every user-facing update (field access `update: nobodyField`, `readOnly` in the panel with a TR+EN hint to "`Lisans işlemleri`" (License actions); submitted values are stripped for panel/REST/bulk/MCP/Local API with access). It changes only through these endpoints, payment fulfilment/refund/dispute and the L5 rule engine (server code, `overrideAccess: true`, each with `req.context.licenseTransition`, exactly one status-log row); create still sets the initial status. Denied audit (`src/lib/licensing/admin/denied-audit.ts`, no schema change): every refusal after the caller is identified as a user (403 guard failures, 404/415/413/400, 409 stale/invalid_transition/confirmation) writes `security-audit` `result denied` with `reason` = response code, `note` = `count=<n> http=<status>`, IP /24 or /48 prefix only, `actorUser` only for users-collection callers, `target` if it exists, `nonce denied:<hash>:<window ms>`; at most one row per (actor or prefix, action, code) per 10 minutes; the window is reserved in memory before the serial writer lock, so repeats write nothing (`count=1` stays) and at most 4 denied-audit writes run at once. Anonymous 401s, successes and replays write nothing; no security event (no fitting type).
